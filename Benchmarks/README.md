# Benchmarks

Every benchmark checks what it measured. Replays compare each checkpoint with the pinned reference emulator and stop at the first mismatch. Each JSON report records the source revision and the host it ran on.

| Report | Command | What it measures | Recorded result |
| --- | --- | --- | --- |
| [First bytes](first-bytes.md) | `swift run -c release ThrushBench` | A prompt, cursor query and Up key through the core | Median across five quiet hosted M1 runs was 8.94 MiB/s (8.66–10.78). Median per-run p95 was 1,000 ns for the prompt and 625 ns for the cursor query |
| [Comparison](comparison.md) | `python3 scripts/comparison/run.py --toy-box ../toy-box --profile` | Nine 1 MiB recorded and synthetic workloads through ThrushCore, libghostty-vt 1.0.2 and @xterm/headless 6.0.0 at two grids and two chunkings, with screen checks, allocations and a profile | Thrush beat xterm in all 36 conditions, by 2.11–2.28× on wide text. It matched every reference screen and reached 0.12–1.05× libghostty-vt across the matrix |
| [Headless replay](headless.md) | The same command | Sustained ASCII, recorded shell, Vim and Codex output, bounded queues and resize | 193 MiB/s at 80 × 24, against a 100 MiB/s target. Worst full-history resize p95 0.582 ms, against 8.333 ms |
| [Mac rendering](rendering.md#first-mac-measurement) | `swift run -c release ThrushBench --render .build/demo/mac/Thrush.app` | Shader compile, first content, warm redraws, theme switches and idle frames in the packaged Mac app | Warm full grid p95 0.274 ms CPU and 0.102 ms GPU. Zero frames while idle or hidden |
| [iPhone simulator rendering](rendering.md#first-iphone-simulator-measurement) | `scripts/benchmark-simulator.sh "$udid" .build/demo/simulator/Thrush.app .build/benchmarks/render-simulator.json` | The same Release workload and an actual UIKit background transition | Warm full grid p95 8.788 ms CPU and 0.227 ms GPU on a contended host. Zero submissions in 4.079 s backgrounded |
| [Native input](rendering.md#native-input-and-echo-latency) | `swift run -c release ThrushBench --interactions .build/demo/mac/Thrush.app` | Composition, paste and keys from the native responder to the socket and back | [Mac report](interactions-mac.json), p95 0.066 ms key to socket write and 0.440 ms key to receipt. All 20 echoes reached Metal |
| [Connection](connection.md) | `swift run -c release ThrushBench --connection` | Attach, resume, takeover, reclaim, expiry, recovery and in-band replay over loopback | Foreground ready and replay to Up p95 0.872 ms |
| [Real PTY](pty.md) | `scripts/check-pty.sh --toy-box ../toy-box` | Historical pinned-server logs, reader comparisons and exit under pressure | The paced 1 MiB/s log arrived intact. The suspended reader missed the exit control. [Candidate comparison](pty-recovery.md) |
| [PTY recovery](pty-recovery.md) | `scripts/check-pty.sh --recovery --working-tree --toy-box ../toy-box` | In-band screen repair, native Mac input and exit delivery after a stall | Restored all 24 rows and accepted input. A 4.505 s post-exit stall retained the final screen. At 7.010 s and 8.502 s, the raw socket closed abnormally. [Run data](pty-candidate.json) |
| [Native PTY workflows](live-workflows.md) | `python3 scripts/live-workflow/launch.py --help` | Native Shell, Vim, Codex and lifecycle checks against real PTYs on Mac and iPhone Simulator | [Mac](live-workflows-mac-hosted.json) 34/34 checkpoints, 28,910 bytes. [iPhone](live-workflows-iphone.json) 34/34, 22,667 bytes. Received and applied counts match the relay on both |

Build the sample app with `scripts/build-demo.sh mac` before the rendering and input benchmarks. Run them from a logged-in, unlocked graphical session, since a locked display returns no presentation timestamps.

The first-bytes row comes from five quiet runs on a hosted Apple M1 virtual Mac. The native PTY workflows ran on hosted Mac and iPhone Simulator jobs. The iPhone simulator rendering run used a contended hosted arm64 Mac on macOS 27.0.1. The remaining Mac figures come from a contended M1 Max on macOS 27.2.1. Compare runs on the same machine and power state, and use five quiet passes before setting a timing gate. Physical iPhone timings need a device run.
